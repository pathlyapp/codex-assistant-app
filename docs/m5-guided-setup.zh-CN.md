# M5 小白用户向导工作包

## 1. 目标与范围

本工作包落实 `WP-501` 至 `WP-505`，覆盖 `PROD-001`、`PROD-003`、
`UX-001` 至 `UX-004`、`UX-010`、`UX-020` 至 `UX-030`、`DIAG-003`、
`DIAG-007`、`ROUT-002` 和 `SECR-004`。

用户目标只有三个：

1. 确认 ChatGPT 与 Codex 是否可用。
2. 填写 Router、可选 Key 和模型，并完成真实验证。
3. 失败后知道下一步，且确认原配置是否已经恢复。

本轮不改变 Rust installer-core 的六个内部阶段，不新增支付、账号、遥测、自动启动
ChatGPT 或离线分发官方应用。本轮也不替代 M6 的结构化诊断 ZIP、定向修复和日志轮转。

## 2. 事实源

- 首页、配置页和诊断页只消费同一次 `SystemStatusV1`。
- 主动作只消费 `recommendedAction`，前端不重新推导业务结论。
- Router 模型只来自真实 `/v1/models`。
- 配置成功只接受 installer-core 在 `/v1/responses` 和最终复核完成后返回的成功结果。
- 恢复状态只来自 `rollback` 阶段，不根据日志文本猜测。
- 配置期间不启动 ChatGPT；成功后仍需用户明确点击“重启并打开 ChatGPT”。

## 3. 页面结构

### 3.1 首页

首页保持工作台结构，不增加欢迎页或营销内容：

- 顶部：整体状态与一个主动作。
- 中部：ChatGPT、Router、Codex 配置三个固定状态。
- 底部：当前 Router、模型和凭证状态；最多两个次要操作。

### 3.2 服务配置

服务配置页固定显示四个用户步骤：

| 用户步骤 | 数据来源 | 完成条件 |
| --- | --- | --- |
| 1. 环境检测 | `SystemStatusV1.platform/architecture`、`preflight` | 状态读取成功且 preflight 完成 |
| 2. 安装或修复 | `SystemStatusV1.app`、`install_chatgpt` | 官方应用已检测或安装阶段确认跳过 |
| 3. 连接服务 | `validate_router`、`validate_router_response`、`configure_codex` | 模型、Responses 和配置写入全部完成 |
| 4. 验证完成 | `verify`、可选 `rollback` | 最终复核成功；失败时显示实际恢复结果 |

内部六阶段仍显示在进度详情中，不扩充用户步骤。步骤完成态必须来自真实状态或已完成
阶段，不能只因步骤序号靠前就显示完成。

配置表单只保留：

- Router URL。
- “该服务无需 Key”开关。
- 遮罩 Key 输入和显隐按钮。
- “测试并读取模型”。
- 真实模型选择。
- “应用并验证”。

ChatGPT 缺失时，Windows 在前置状态行显示官方安装动作。macOS 不提供伪安装动作，
只按核心推荐动作引导到官方安装说明。

### 3.3 进度与结果

- 进度百分比和阶段状态来自 `StageEventV1`。
- 技术日志默认折叠；失败后自动展开。
- 成功页必须显示官方应用状态、规范化 Router、模型、最近验证时间和恢复能力。
- 成功页只有“重启并打开 ChatGPT”是主动作。
- 失败页只有“修正并重试”是主动作。
- “复制诊断”和“查看技术日志”始终作为次要操作。
- 自动回滚成功必须明确显示“已恢复到操作前状态”。
- 自动回滚失败必须明确要求先复制诊断，且不得继续暗示配置安全。

## 4. 诊断与隐私

一键复制摘要包含：

- 助手版本、状态 schema、平台和架构。
- ChatGPT、Codex 配置、Router 状态。
- 规范化 Router、模型和最近验证时间。
- 配置来源、备份状态、最后事务 ID 和推荐动作 ID。
- 最近失败阶段和脱敏错误。

复制摘要不得包含：

- Access Key、Bearer 或 URL userinfo。
- query 中的 key/token/api_key/access_token。
- Windows、macOS 或 Linux 的完整用户目录。
- 原始配置文件正文和探针响应正文。

前端复制摘要执行第二层脱敏；installer-core 的统一 redactor 仍是错误和日志进入前端前
的第一层。M6 必须将结构化诊断包改为 Rust command 生成，并在导出前执行阻断扫描。

## 5. 平台与可访问性

- 当前版本明确使用浅色模式，使用系统字体，不加载网络字体。
- 保留 Tauri/系统原生窗口框架，不自绘标题栏。
- 标准验收尺寸为 `940x720` 和 `820x640`。
- 等效窄视口下侧栏折叠为图标栏，步骤隐藏长标签，表单按钮改为纵向排列。
- 所有状态同时使用图标、文字和颜色。
- 四步指示器维护 `aria-current`。
- 结果面板出现后接收焦点。
- 确认对话框关闭后焦点返回触发控件。
- `125%`、`150%`、仅键盘和屏幕阅读器仍需 Windows/macOS 实机验收。

## 6. 自动验收

`tools/windows-e2e.ps1` 必须断言：

1. 四步 ID 固定为 `environment,app,service,verify`。
2. 环境和 ChatGPT 前置状态与 `SystemStatusV1` 一致。
3. 成功后四步全部完成，摘要包含最近验证和恢复能力。
4. 失败结果存在持续可见的复制诊断入口。
5. 失败结果只有一个主重试动作。
6. verify 故障自动回滚后显示“恢复到操作前状态”。
7. 配置期间 ChatGPT 进程数保持为零。
8. 原有事务 manifest、文件指纹、Responses 证据和恢复 round-trip 断言继续通过。
